WHY MCP

从公开线索，走向可追溯的专业判断

公开信息适合发现线索，但不能替代专业专利数据。缺少明确的数据范围和原始记录时，通用AI 容易把少量案例当成整体、把媒体转述当成专利事实、把旧状态当成当前状态。

✗ 没接入 PatSnap MCP Suite 前通用AI 主要依赖模型记忆、网页片段和人工转述
✗
公开报道被当成完整专利范围

几件媒体关注的专利被用来概括企业全部布局，造成漏检和偏差。

✗
媒体转述被当成专利原文

权利要求、申请主体和时间信息被省略，结论难以回到原始文献确认。

✗
单件专利被误读成整体趋势

看到一个技术案例便推断企业主攻路线，缺少集合层面的验证。

✗
旧网页被当成当前法律状态

后续许可、转让、质押、复审或无效变化没有被纳入判断。

✗
研究成果散落在个人文件中

筛选结果、判断依据和专家标引难以被团队持续更新与复用。

✓ 接入 PatSnap MCP Suite 后为 AI 提供专业、结构化、可追溯的专利数据与能力

用量与 Credits

连接本身不扣费；只有实际调用专业数据和分析能力时才使用 Credits。

01
连接不消耗 Credits

创建 MCP Key、添加 Server 和完成连接均不扣除额度。

02
专业调用按任务深度计费

不同 Server、任务规模和分析深度对应不同 Credits。

03
Fetch 按数据域逐层取用

读取基础信息、全文、附图或关联数据时，只按实际调用的内容层级使用相应额度。

04
